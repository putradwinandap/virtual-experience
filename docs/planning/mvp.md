# MVP

## Objective

Validate whether a structured, open, scenario-based experience library provides meaningful learning value before building a dedicated application.

## MVP product

The MVP is a **GitHub repository + Markdown content system**.

No custom web platform is required for MVP validation.

## In scope

- Programming/software engineering as the first domain
- A documented topic/scenario content model
- A reusable scenario template
- Clear contribution guidelines
- Clear provenance classification
- A small, coherent taxonomy
- Multiple scenarios under the same topic where useful
- Seed experiences that demonstrate the intended quality bar
- GitHub Issues for project work
- Repository-resident project context for human and AI contributors

## Out of scope

For the initial MVP:

- dedicated frontend application
- user accounts
- database
- ratings or reputation system
- recommendation engine
- AI tutor/chat interface
- gamification
- interactive browser simulations
- broad multi-domain taxonomy
- monetization

These ideas may be explored later if content usage demonstrates a real need.

## MVP validation questions

The MVP should help us answer:

1. Do learners find scenario-based exposure useful compared with ordinary explanations?
2. Can contributors describe experiences in a consistent enough format?
3. Can multiple scenarios around the same topic coexist without becoming confusing?
4. What metadata is actually useful for discovery?
5. Which parts of the scenario format feel natural or overly rigid?
6. Does the repository remain navigable as the number of experiences grows?
7. What problems would a dedicated web application genuinely solve?

## Initial completion criteria

The first MVP milestone can be considered coherent when the repository has:

- project vision and principles
- AI/contributor operating rules
- experience template
- contribution guide
- initial taxonomy
- at least several high-quality seed scenarios across multiple topics
- at least one topic with multiple distinct scenarios
- documented feedback and next-step questions

The exact seed-scenario count should be decided based on quality and learning coverage rather than an arbitrary volume target.
